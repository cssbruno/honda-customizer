## Observed head unit

The owner's supplied connection-report photo shows Android 10 on `sprd ums512_1h10_Natv`, SYU service `2.23.0718.1700 / 2123071817`, and profile **0x4012A (262442)**. The connection uses `com.syu.ms.toolkit → com.syu.ms/app.ToolkitService`. This establishes connection and decoder identity, not successful setting reads or writes. The photo does not show the installed Customizer version.

## Exact source route

Follow-up photographs received on 2026-09-16 also show decoder version
**CRI V1.13.108BYPT** and all 22 mapped settings as “sem retorno”. The
[data-request investigation](XP-DATA-REQUEST.md) identifies a stock entry
request omitted through 3.4.3 and restored in 3.4.4. The version string is
service-reported metadata, not proof of a raw-CAN contract.

Reference CANBUS APK: Joying UIS7862, SHA-256 `98103bc4b64cfc87cd5957a3659304c078a69d8388ae4878fe4950119f15110d`, recorded in `honda-cluster-analysis/fyt/source.json`.

- `FinalCanbus.CAR_XP1_2016SIYU_H = 0x4012a`: XP Honda 2016 Civic High. This is the vendor profile name, not a deduction about the owner's car model year.
- `HondaIndexActi.init`: this profile is neither WC nor a BNR direct-entry profile; `showRZCSettings` explicitly excludes it. The resulting route opens `CommpassActi`.
- `CommpassActi.onCreate`: button `0x7f0b0096` registers listener `$7`. Freshly extracted `$7.onClick` opens `AcrivitySiYuSettings` without substituting a different decoder.
- `AcrivitySiYuSettings.onResume`: its explicit `0x3012a / 0x4012a` branch and subsequent predicates determine the XP rows. All branch execution in the saved audit uses **0x4012a**.
- Layout `layout_298_siyu_settings`: key/remote-unlock and beep-volume rows start GONE. Runtime visibility is applied on top of those defaults.

## Persistent settings

22 scalar settings are visible and have complete command/feedback contracts. The [contract table](xp-4012a-contracts.json) records command 105, keys, callback fields and legal options. [Source execution](xp-4012a-source-audit.json) records every writer path for every legal starting value, as well as the exact visibility decisions. Existing source-backed labels/renderers in this same activity supply the option meanings. Readback is validated as a full integer; WC byte masking and offsets are not used.

Fields: `58, 59, 60, 61, 62, 63, 64, 66, 69, 70, 72, 73, 74, 75, 76, 78, 79, 80, 81, 82, 87, 114`.

Reproduce the offline writer/visibility audit:

```sh
python3 tools/audit_xp_source.py /path/to/com.syu.carinfo.honda.AcrivitySiYuSettings.smali --output /tmp/xp-audit.json
```

The app uses separate XP control objects and an exact one-profile allowlist. Neighboring XP IDs are not enabled by inference. BNR/RZC/WC control objects cannot dispatch on this profile, and XP control objects cannot dispatch on those profiles. Shared settings activity code is traced for XP independently; the app does not call BNR commands as a fallback.

## Limits

The maintenance value is visible on this profile, unlike the previously supported BNR profiles. Fields 135–137 need a separate multi-field freshness/format implementation and remain outside this persistent-setting patch. Maintenance reset, restore defaults, TPMS calibration and language still lack completion/readback evidence. Version 3.4.1 adds the first three as explicitly unconfirmed one-shot requests; see [ready actions](XP-READY-ACTIONS.md). Units, ACC/LKAS tones, collision/lane-departure settings, reverse tone and seat/tailgate rows hidden by this XP route are not enabled.

Settings subscribe without replaying the service cache. Missing, stale and invalid feedback stays unavailable; a successful dispatch cannot confirm state. The supplied service version is newer than the inspected service APK, so physical feedback/write validation on this unit remains required. The connection report alone cannot establish those results.

External source hashes are in [the source manifest](xp-4012a-source-hashes.json). Vendor executable code and the supplied photo are not bundled in the app.
